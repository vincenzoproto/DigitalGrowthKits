# Repeat Guest Engine — First Sale Playbook

## Goal
Move a positive hotel reply to a qualified €690 founder setup without promising unsupported integrations or sending payment before feasibility is confirmed.

## Reply handling

### A. Positive / curious
Ask for only the information needed to qualify:
- PMS / booking system used;
- whether historical guests can be exported to CSV;
- approximate number of guest records;
- whether marketing eligibility / unsubscribe status can be identified;
- direct-booking URL;
- primary language(s);
- main target: repeat bookings, win-back, or low-season fill.

Then propose a 15-minute setup review.

### B. Wants price immediately
Answer:
- Founder implementation: €690 one-time for the first 3 completed purchases.
- Standard price afterward: €990.
- One property, database mapping, segmentation, 3 core automations, reporting view and handover.
- Hosting/email provider and unsupported custom integrations are separate.

Do not send checkout until the qualification points in `FOUNDER-SCOPE.md` are confirmed.

### C. Interested but technical concern
Do not bluff. Identify the exact PMS/export constraint first. If a clean CSV export is available, continue. If custom integration is required, scope separately.

## 15-minute setup review agenda

Minute 0–3: property goal and current repeat-guest process.
Minute 3–7: PMS, export, database size, marketing-status source.
Minute 7–10: show the local CSV segmentation demo with synthetic/test data.
Minute 10–13: explain the 3 launch automations and what remains excluded.
Minute 13–15: confirm feasibility, delivery inputs and next step.

## Close condition

Only after feasibility is confirmed:
1. restate the agreed scope in one short email;
2. send the €690 checkout link;
3. mark CRM as Payment pending;
4. after verified payment, mark Closed-won and start onboarding.

## Onboarding request after payment

Request through a secure agreed channel:
- property details and staff contact;
- approved CSV/export;
- field definitions;
- sender domain/address;
- direct-booking URL;
- brand assets;
- approved languages;
- campaign/offer inputs;
- confirmation of marketing eligibility and suppression responsibilities.

Never request guest-level data in an initial sales email or public form unless the implementation and data handling process is already agreed.

## Demo rule

The public/demo analyzer processes CSV locally in the browser and does not send guest communications. Use synthetic or seed data during sales demonstrations. Never upload a prospect's real guest database merely to prove the concept.
